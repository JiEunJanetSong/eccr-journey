01 · 세 가지 산출물을 구분하는 시스템 지도

ECCR는 교사의 읽기 수업 계획, 수정 가능한 교재 제작, 정적 듣기 앱을 연결합니다. 재현의 첫 단계는 어떤 판본의 무엇을 만들 것인지 정하는 것입니다.

구성요소

  • 제작 자료: 원고, 승인된 그림, 글꼴, 녹음, 스크립트, 페이지 대응표입니다. 다시 만들 수 있도록 함께 보존합니다.
  • 인쇄 자료: Book 1–9, Book 0, 병렬 연습책 Reader A–C, 권별 평가책, 기초 음가 평가, 쓰기책입니다. 서로 다른 학습 목적을 가진 별도 산출물입니다.
  • 듣기 소프트웨어: picturebook/의 글자 터치 화면과 audio/의 목록·연속 재생 화면이 하나의 데이터 원본을 씁니다. 작업 여정 아카이브는 이와 별개인 문서 사이트입니다.

제작 절차

  • 목표 목록에 PDF 판본, 대상 페이지, 언어, 녹음, 화면 크기, 오프라인 요구를 적습니다.
  • 변경 전 원본 경로·쪽수·해시를 자료 목록에 기록합니다. 새로 만든 자료는 검토 전까지 후보본으로 관리합니다.

검증

  • PDF가 최종본이라는 사실만으로 배포된 듣기 앱도 그 PDF를 사용한다고 볼 수 없습니다. 둘을 따로 대조합니다.
확인한 공개 앱 스냅샷(3b87245)은 Book 1–7과 이전 두 언어 문구를 포함합니다. 인쇄 폴더에는 교정된 Book 1–9와 후속 보조 자료가 있습니다. 현재 앱 재현과 최신 PDF 통합은 서로 다른 작업입니다.

02 · 대화를 검증 가능한 제작 조건으로 바꾸기

좋은 제작 조건표는 교사가 제공한 내용, AI의 제안, 교사의 후속 교정을 구분합니다. 날짜만으로 서로 다른 판본의 충돌이 해결되지는 않습니다.

구성요소

  • 학습자 본문과 번역 참고문을 분리합니다. 야우의 영어 뜻풀이는 Janet의 Twi 이해를 도왔고, 후속 결정에 따라 Book 4–6 학습자용에서는 삭제되었습니다.
  • 페이지별 기록에는 출처 메시지, 책, PDF 순번, 인쇄 쪽 번호, 정확한 문구, 그림 요구, 승인 상태를 둡니다.
  • 최신의 명시적 내용 결정과 확인한 대상 파일을 기준으로 삼습니다. 대화 원문은 그대로 두고 요약·번역 설명을 편집문으로 표시합니다.

제작 절차

  • AI 생성 전 요청마다 합격 조건을 적습니다. 예: 염소 두 마리와 아이 두 명, 또는 그림 하나와 연결된 문장.
  • 피드백이 오면 이전 문구 → 확정 문구 → 영향받는 산출물을 기록합니다. 평가책과 음성 매핑도 영향 목록에 포함합니다.

검증

  • “네 글자”는 단어 길이 조건이며 문장당 네 단어라는 뜻이 아닙니다. 단어가 짧다는 것만으로 해독 가능성이 입증되지도 않습니다.

03 · 글은 편집 가능한 상태로, 그림은 별도 자산으로

초기 Book 2는 XeLaTeX로 그림 위·Twi 조판 아래 구조를 만들었고, 이후 제작기는 ReportLab으로 PDF를 정밀 배치합니다. 공통 원칙은 생성 그림 안에 본문 글자를 넣지 않는 것입니다.

구성요소

  • 승인된 이미지, 장면 프롬프트, 참조 원본을 함께 저장합니다. 반복 인물의 얼굴·옷·키 비율·장면 연속성을 유지합니다.
  • 그림 생성은 시각 내용의 제작·변경에 사용합니다. 가운데 정렬·여백·쪽 번호·문구 교정은 조판 코드로 처리합니다.
  • 경로별 도구가 다릅니다. 초기 TeX는 XeLaTeX·fontspec을, 후속 PDF 제작기는 Python·ReportLab·PyMuPDF·Pillow 및 일부 pypdf를 씁니다. 글꼴 파일도 입력 자료입니다.

제작 절차

  • 글과 그림을 합친 작은 샘플을 먼저 검토한 뒤 같은 규칙을 책 전체로 확장합니다.
  • PDF를 이미지로 렌더링하고 본문도 추출합니다. ɔ·ɛ·Ɔ 같은 Twi 글자, 글자 크기, 신체 잘림, 그림 겹침, 실제 쓰기 공간을 점검합니다.

검증

  • 동일한 그림을 재현하려면 승인된 이미지 파일을 재사용합니다. 이미지 프롬프트를 반복한다고 같은 그림이 그대로 만들어지지는 않습니다.
  • 기존 TeX·Python 스크립트에는 특정 컴퓨터의 글꼴 경로가 있습니다. 다른 컴퓨터에서는 해당 경로를 먼저 맞춰야 합니다.
보관된 초기 book2.tex는 현재의 20쪽 A4 Book 2가 아닌 이전 A5 시기의 원고를 만듭니다. 제작 기법의 예시이며 후속 모든 교정을 한 번에 재현하는 명령은 아닙니다.
pdfinfo book.pdf
pdffonts book.pdf
pdftotext -layout book.pdf -
pdftoppm -png -r 120 book.pdf /tmp/eccr-page

04 · 인쇄판과 앱판을 페이지 대응표로 관리하기

같은 책에서 여러 목적의 판본이 나올 수 있습니다. 보존된 그림이 같더라도 빈 페이지를 지우면 페이지 순번은 바뀝니다.

구성요소

  • 9월 15일 앱용 파생판은 Book 1–9의 빈 면 15쪽을 제거하고 original_pdf_page → app_pdf_page를 기록합니다. 당시 PDF만 제작되었고 앱에는 올리지 않았다고 명시합니다.
  • 인쇄 파생판은 펼침면과 제본 조건을 유지합니다. 인쇄 쪽 번호, 실제 PDF 페이지, 화면 인덱스는 서로 다른 세 가지 식별자입니다.
  • 최종 본책의 쪽 번호 교정은 짝수 왼쪽·홀수 오른쪽입니다. 이전 제본 하위 폴더에는 다른 실험판도 있으므로 한 폴더의 README를 모든 판본에 적용하면 안 됩니다.

제작 절차

  • 원본 판본을 지정하고 보존한 뒤 새 출력 위치에 제작합니다. 보존하는 모든 페이지마다 대응표 한 행을 저장합니다.
  • 이미지 파일명과 음성 항목에 같은 대응표를 적용합니다. 조판이 바뀌면 터치 영역을 다시 측정합니다.

검증

  • 보존된 페이지를 렌더링 또는 픽셀 비교로 원본과 대조합니다. 빈 면·표지 순서·여백·쪽 번호 방향·전체 쪽수를 확인합니다.
{
  "book": 1,
  "original_pdf_page": 12,
  "app_pdf_page": 9,
  "original_asset": "book1/page-12.jpg",
  "new_asset": "book1/page-09.jpg"
}

05 · 명시한 규칙으로 평가와 병렬 읽기 자료 만들기

같은 디자인을 재사용하는 것만으로는 부족합니다. 자료마다 학습 목적과 검증 규칙이 필요합니다.

구성요소

  • 권별 평가는 해당 책에서 가르친 내용과 연결합니다. 기초 평가는 수업 전 음가를 확인하며 학습자 항목과 교사 기록지 순서를 맞춥니다.
  • Reader A–C는 각 40쪽·12개 글이며 계획된 음가 범위를 공유합니다. manuscripts.json은 문장·합성 낱말·질문·목표 모음·장면을 정의합니다.
  • 제작기는 누적 모음 범위·단어 길이·VC/CVC 조건·문장 수·글의 중복·PDF 쪽수·쪽 번호 방향·이야기 페이지당 그림 하나를 검사합니다.
  • 합본 Book 0는 90쪽이고 이전 80쪽 책은 Book 0-pre로 보존합니다. 쓰기 4선의 줄 간격은 2.5mm, 한 세트 높이는 7.5mm입니다.

제작 절차

  • 조판 전에 원고 결정을 구조화한 기록으로 만듭니다. 같은 기록에서 교사용 정답표를 생성합니다.
  • 어휘·배치 검사를 한 뒤 야우가 음가·교수 순서·뜻·학습자 준비도를 검토합니다.

검증

  • A–C는 계획 범위를 공유하는 연습책이지 동등성이 검증된 검사지가 아닙니다. 네 글자 조건과 자동 철자 검사는 발음이나 수업 효과를 검증하지 않습니다.
전체 제작기는 보관된 그림과 로컬 글꼴 설정에 의존합니다. 빈 작업 폴더에서 시작하는 실습은 이 입력을 준비하거나 새로 만들어야 합니다. 최종 PDF 전체를 만드는 하나의 공통 명령은 없습니다.

06 · 녹음을 정확한 인쇄 문구 단위에 연결하기

교사의 녹음은 배포 자산이 됩니다. 대본 필드는 라벨이며, 실제 녹음도 같은 내용을 말한다는 증거는 아닙니다.

구성요소

  • 원본 녹음을 보존하고 터치할 낱말·문장·제목 단위로 나눈 뒤 정확한 인쇄 문구 옆에 클립 경로와 언어를 기록합니다.
  • 자동 전사는 시간 구간 초안에만 사용합니다. Twi 정확성·앞뒤 소리 잘림·쉼 누락·인쇄되지 않은 설명 음성을 직접 듣고 확인합니다.
  • 실제 두 언어 학습자 페이지에는 언어별 클립을 둡니다. 수정된 Twi 전용 Book 4–6에서는 삭제된 영어 뜻풀이의 재생도 제거합니다.
  • recordingMissing은 음성 합성 대체를 막습니다. GitHub Pages는 포함된 MP3와 빈 TTS API 설정을 사용하므로 교사의 Mac이 켜져 있을 필요가 없습니다.

제작 절차

  • 문구 → 원본 녹음 → 시작/끝 → 출력 클립 표를 만듭니다. 등록 전에 실제로 듣고 승인합니다.
  • 문구가 바뀌면 재녹음 전에 실제 클립을 대조합니다. 철자 교정만으로 소리가 달라지는 것은 아닐 수 있습니다.

검증

  • 각 클립의 시작·중간·끝을 듣고 빠른 항목 전환을 시험합니다. 반복 사이 쉼이 있고 playbackRate가 1인지 확인합니다.
ffmpeg -y -i source.m4a -ss 12.40 -to 14.85 \
  -codec:a libmp3lame -b:a 96k \
  picturebook/audio/book8/page-03-01.mp3

ffprobe -v error -show_entries format=duration \
  -of default=noprint_wrappers=1:nokey=1 \
  picturebook/audio/book8/page-03-01.mp3

07 · 종이·그림·소리를 묶는 데이터 규격

window.ECCR_A4_BOOKS가 두 듣기 화면에 데이터를 제공합니다. 책은 페이지를, 페이지는 이미지와 음성 항목을 담습니다.

구성요소

  • Book: 고유 id·title·assetDir·pages. Page: title·image·audio. Audio item: text·speechText·audioSrc 또는 recordingMissing·lang·box 또는 boxes입니다.
  • 터치 영역은 페이지 이미지 위의 투명 버튼입니다. x·y·w·h는 전체 이미지 대비 백분율이며 픽셀값을 그대로 쓰면 화면 크기가 바뀔 때 위치가 어긋납니다.
  • picturebook/은 audioSrc를 그대로 사용하고 audio/는 ../picturebook/을 앞에 붙입니다. 데이터를 공유해도 상대 경로 규칙은 구분합니다.

제작 절차

  • 확정 PDF를 순서대로 JPEG로 만듭니다. 글자를 누르기 충분하되 이웃 문구와 겹치지 않는 사각형을 측정한 뒤 백분율로 바꿉니다.
  • 이미지·표시 문구·해당 클립을 함께 등록합니다. 전체 도서관으로 확장하기 전에 한 페이지부터 시험합니다.

검증

  • 참조 파일 존재와 0–100% 영역을 검사합니다. 폰과 데스크탑에서 실제 위치를 확인합니다. 좌표값이 유효하다고 배치도 정확한 것은 아닙니다.
{
  text: "Sam has a cap.",
  speechText: "Sam has a cap.",
  audioSrc: "audio/book7/page-04-01.mp3",
  box: { x: 47, y: 28, w: 36, h: 8 },
  lang: "en"
}

// x = leftPixel / imageWidth * 100
// y = topPixel / imageHeight * 100
// w = boxWidth / imageWidth * 100
// h = boxHeight / imageHeight * 100

08 · 작은 실행 코드와 명시적인 재생 상태

앱은 HTML·CSS·일반 JavaScript와 HTML audio 요소를 사용합니다. 필수 프런트엔드 프레임워크·데이터베이스·로그인·서버 실행 환경은 없습니다.

구성요소

  • 책이나 페이지를 바꾸면 재생을 멈춥니다. 다른 문장을 누르면 이전 재생을 무효화한 뒤 새 녹음을 시작합니다.
  • playbackToken은 현재 재생과 이전 재생에서 늦게 도착한 ended/error 이벤트를 구분합니다. Audio Practice의 sequenceToken은 이전 페이지 연속 재생을 취소합니다.
  • 반응형 CSS는 모바일에서 조작부 배치와 페이지 폭을 바꿉니다. 책 이미지와 터치 영역 레이어는 항상 함께 확대·축소되어야 합니다.

제작 절차

  • 책 선택 → 페이지 표시 → 터치 영역 표시 → 항목 재생을 구현하고, 취소와 누락 음성을 명시적으로 처리합니다.
  • 목록 화면도 같은 콘텐츠 규격을 재사용하여 원고가 따로 중복되지 않게 합니다.

검증

  • A→B를 빠르게 누르기, 재생 중 페이지 변경, 페이지 연속 재생 중 책 변경, 누락 음성 선택을 시험합니다. 이전 표시나 소리가 남지 않아야 합니다.

09 · 오프라인 준비: 전체 저장과 앱 재시작 확인

온라인에서 페이지가 보인다는 것만으로 오프라인 사용이 입증되지는 않습니다. 그림과 음성을 모두 저장하고 앱을 닫은 뒤에도 사용할 수 있어야 합니다.

구성요소

  • manifest.webmanifest는 설치 정보를, pwa.js는 서비스 워커 등록과 진행 표시를, offline-assets.js는 필수 파일 목록을, sw.js는 저장·갱신·제공을 담당합니다.
  • Save offline은 CACHE_ALL_OFFLINE_ASSETS를 보내고 진행 메시지가 파일 수를 셉니다. 패키지가 모두 있어야 Offline ready가 표시됩니다.
  • 브라우저는 MP3의 일부 구간만 요청할 수 있습니다. createRangeResponse는 저장된 파일에서 해당 바이트 구간을 206 응답으로 제공해 오프라인 음성을 재생합니다.

제작 절차

  • 내용을 바꾸면 자산 목록을 다시 만들고 새 캐시 이름과 자산 쿼리 버전을 사용합니다. 생성되는 목록은 수동 편집하지 않습니다.
  • 온라인에서 Offline ready까지 저장합니다. 앱을 완전히 닫고 네트워크를 끊은 뒤 같은 브라우저·프로필로 다시 열어 그림과 소리를 시험합니다.

검증

  • 폰과 데스크탑에서 각각 확인합니다. 이미 열린 화면에서 성공한 것만으로 오프라인 재실행 검증을 대신할 수 없습니다. 브라우저 저장소는 삭제·회수될 수 있습니다.

10 · 근거를 남기고 배포하여 다음 제작자의 출발점 만들기

반복 가능한 배포는 승인된 입력과 산출물을 연결하고 실제 배포 파일을 검증하며, 교사가 더 확인해야 할 부분을 설명합니다.

구성요소

  • 확인한 package.json의 check는 여섯 JavaScript 파일에 node --check를 실행합니다. 문법만 검사하며 파일 연결·학습 내용·터치 위치·음성은 검증하지 않습니다.
  • 앱의 GitHub 워크플로는 main 푸시 시 저장소를 정적 Pages 산출물로 올립니다. 개발 전용 자료와 비공개 원문은 배포 패키지 밖에서 관리합니다.
  • 배포 기록에는 원본 판본·페이지/음성 목록·캐시 버전·변경 파일·자동 검사·기기 확인·미해결 질문을 적습니다.

제작 절차

  • 문법·파일 연결 검사, PDF 렌더링, 클립 듣기, 모바일 조작, 오프라인 재실행을 각각 수행합니다. 서로 다른 오류를 확인하는 검사입니다.
  • 배포 완료 후 공개 URL에서 새 리비전과 자산 경로를 확인합니다. 동기화 완료라고 말하기 전에 실제 메타데이터와 승인본을 대조합니다.
  • 다음에 할 수 있는 작업을 적은 인계서를 저장합니다. 재제작에 필요한 소스와 승인 자산을 포함해야 하며 프롬프트만으로는 완전한 소스 패키지가 되지 않습니다.
